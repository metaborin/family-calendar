# 家族カレンダー（最小構成版）

家族の予定を入力して、1か月分を **A4縦1ページ** に印刷するための小さなWebアプリです。

手書きの家族カレンダーをそのままパソコンで置き換えることを目的にしています。
会員登録もログインも不要で、入力した内容は**お使いのブラウザの中だけ**に保存されます。

---

## 1. 公開版（GitHub Pages）

インストール不要で、次のURLからすぐに使えます。

**https://metaborin.github.io/family-calendar/**

### 開き方

1. 上のURLをブラウザで開きます。
2. すぐに今月のカレンダーが表示されます。準備や設定は必要ありません。
3. よく使う場合はブックマーク（iPhoneなら「ホーム画面に追加」）しておくと便利です。

### 対応している端末

| 端末 | 使い方 |
| --- | --- |
| パソコン（Windows / Mac） | そのまま利用できます。印刷にも対応しています。 |
| iPhone / Android | 表示・入力できます。**表は左右に指でスクロール**してご覧ください。 |
| iPad / タブレット | 表示・入力できます。同じく横スクロールで全体を確認できます。 |

画面が狭い端末では、6列すべては一度に表示されません。
**表の上を左右にスクロール**すると、隠れている家族の列を確認できます。
（今回はスマートフォン専用の画面は用意していません）

## 2. 予定はどこに保存されるのか（とても重要）

入力した予定と家族名は、**その端末のそのブラウザの中（localStorage）だけ**に保存されます。
インターネット上のサーバーやGitHubには、**一切送信されません**。

そのため、次のような動作になります。**これは不具合ではなく仕様です。**

| 項目 | 動作 |
| --- | --- |
| パソコンで入力した予定 | **そのパソコンのそのブラウザにだけ**保存されます |
| iPhoneで入力した予定 | **そのiPhoneのそのブラウザにだけ**保存されます |
| 端末をまたいだ同期 | **されません**（PCで入力した予定はiPhoneには出ません） |
| 別のブラウザ | **引き継がれません**（Chromeの予定はEdgeには出ません） |
| 他の人が公開URLを開いたとき | **あなたの予定は見えません**（その人の端末には空のカレンダーが出ます） |
| ページの再読み込み | その端末の予定は**残ります** |
| ブラウザのサイトデータを削除 | 予定も**消えます** |
| GitHubへのデータ送信 | **ありません**（ログイン・サーバー・データベースがないため） |

### localhost版から公開版への引き継ぎについて

パソコンで `http://localhost:5173/` を使って入力していた予定は、
**公開版（GitHub Pages）へは自動で引き継がれません。**

localStorage は「どのサイトか」ごとに別々に保存されるため、
`localhost` と `metaborin.github.io` は別のサイトとして扱われます。
公開版を使い始める場合は、お手数ですが改めて入力してください。

> 大切な予定は、印刷やPDF保存で紙・ファイルとして残しておくことをおすすめします。

使用しているlocalStorageキー：

- `family-calendar-mvp:names` … 家族の表示名
- `family-calendar-mvp:schedules` … 年月ごとの予定

保存される形：

```json
{
  "2026-08": {
    "1": { "everyone": "買い物", "member1": "仕事" }
  }
}
```

保存データが壊れて読み込めなかった場合も、アプリが真っ白になることはありません。
初期値で起動し、画面上部にエラーメッセージを表示します。

## 3. できること

- 1日から月末までを縦に並べた予定表を表示する
- 「みんなの予定」＋家族5人分、合計6列に予定を入力する
- 入力すると自動で保存される（保存ボタンは不要）
- 家族の表示名を自由に変更できる
- 前月・次月へ移動する、年と月を直接指定する
- 土曜日を薄い水色、日曜日を薄いピンクで色分けする
- 1か月分をA4縦1ページへ印刷する（PDF保存も可能）

## 5. ローカルで動かす場合

公開版を使うだけなら、この章は読み飛ばして構いません。
自分のパソコンで開発・改造したい場合の手順です。

### 必要な環境

- Windows 10 / 11（他OSでもNode.jsがあれば動きます）
- Node.js 20 以上（[https://nodejs.org/](https://nodejs.org/)）
- Google Chrome、Microsoft Edge などの最近のブラウザ

### 方法A：start-app.cmd をダブルクリックする

1. プロジェクトフォルダの中の **`start-app.cmd`** をダブルクリックします。
2. 初回のみ、必要なファイルの取得（`npm install`）が自動で行われます。数分かかることがあります。
3. 黒い画面（開発サーバー）が別ウィンドウで開き、その後ブラウザにアプリが表示されます。
4. ブラウザが自動で開かない場合は、次のURLを手で入力してください。

   `http://localhost:5173/family-calendar/`

5. 終了するときは、「**Family Calendar dev server**」というタイトルのウィンドウを閉じてください。

> `start-app.cmd` の表示メッセージは英語です。
> Windowsのコマンド画面が日本語を含むバッチファイルを正しく読み取れない場合があるためで、
> 動作には影響しません。

### 方法B：ターミナルから npm コマンドで起動する

```bash
npm install
```

```bash
npm run dev
```

表示された `http://localhost:5173/family-calendar/` をブラウザで開きます。

その他のコマンド：

```bash
npm run build
```

```bash
npm run preview
```

```bash
npm run lint
```

> URLに `/family-calendar/` が付くのは、GitHub Pages の公開URLと
> パスをそろえるためです（`vite.config.ts` の `base` 設定）。
> `http://localhost:5173/` を開いても自動で転送されます。

## 6. 使い方

### 6-1. 家族名を変更する

画面上部の「**家族名の変更**」欄にある6つの入力欄を書き換えてください。

- 1列目：みんなの予定（家族全員の予定・行事・祝日など）
- 2〜6列目：家族それぞれの予定

書き換えた名前はすぐに保存され、表の見出しにも反映されます。

**名前を変えても、入力済みの予定は消えません。別の列へ移動することもありません。**
予定は表示名ではなく、内部の固定ID（`everyone` / `member1`〜`member5`）で管理しているためです。

### 6-2. 予定を入力する

表の中のセルをタップ（クリック）して、そのまま文字を入力してください。

- 日本語入力（かな漢字変換）が使えます
- `Enter` で改行できます
- コピー＆貼り付けができます
- **保存ボタンはありません。入力するとすぐ自動保存されます**
- 入力中のセルは水色の枠で表示されます

### 6-3. 月を変更する

画面上部で操作します。

- 「**前月**」「**次月**」ボタン … 1か月ずつ移動します（年をまたぐ移動にも対応）
- 「**年**」欄 … 年を直接入力します
- 「**月**」欄 … 月を選びます

月が変わっても、それぞれの月の予定は別々に保存されています。混ざることはありません。

### 6-4. 印刷する

1. 印刷したい年月を表示します。
2. 画面右上の「**印刷**」ボタンを押します。
3. ブラウザの印刷画面が開きます。次の設定を確認してください。

   | 項目 | 設定 |
   | --- | --- |
   | 用紙サイズ | **A4** |
   | 印刷の向き | **縦** |
   | 倍率 | **既定 / 100%**（「用紙に合わせる」でも可） |
   | 背景のグラフィック | **オン**（土日の色を印刷する場合） |

4. 「印刷」を押します。

操作ボタン・年月の選択欄・家族名の変更欄は印刷されません。
印刷されるのは、タイトル「家族カレンダー」、選択中の年月、家族名、日付、曜日、入力した予定です。

### 6-5. PDFとして保存する

印刷画面の「**プリンター**」の選択肢で、

- Google Chrome：「**PDFに保存**」
- Microsoft Edge：「**PDFとして保存**」

を選んで保存してください。紙に印刷する場合と同じレイアウトで保存できます。

### 6-6. 印刷しても土日の色が出ないとき

ブラウザの印刷画面で、次を確認してください。

- Chrome / Edge：「**詳細設定**」を開き、「**背景のグラフィック**」にチェックを入れる
- Firefox：「**背景色と背景画像を印刷**」にチェックを入れる

アプリ側では `print-color-adjust: exact` を指定していますが、
最終的には**ブラウザの印刷設定が優先される**ため、上記の確認が必要です。

## 7. GitHub Pages への公開について

### 仕組み

`main` ブランチへ push すると、GitHub Actions が自動で次を実行して再公開します。

1. ソースを取得（checkout）
2. Node.js 22 をセットアップ
3. `npm ci`（依存関係のインストール）
4. `npm run lint`
5. `npm run build`
6. `dist` フォルダを Pages 用の成果物としてアップロード
7. GitHub Pages へデプロイ

ワークフローの定義：`.github/workflows/deploy-pages.yml`

**公開されるのはビルド結果（`dist`）だけ**で、`node_modules` やプロジェクト全体は公開されません。

### 再公開する方法

```bash
git add .
```

```bash
git commit -m "Update calendar"
```

```bash
git push
```

push の1〜3分後に公開版へ反映されます。

手動で実行したい場合は、GitHubのリポジトリ画面で
**Actions** → **Deploy to GitHub Pages** → **Run workflow** から実行できます。

### デプロイが失敗したときの確認場所

1. GitHubでリポジトリを開く
2. 上部の **Actions** タブを開く
3. 失敗した実行（赤い×印）をクリック
4. **build** または **deploy** のジョブを開き、赤くなっているステップのログを確認

よくある原因：

- `npm run lint` でエラーが出ている（コードの書き方の問題）
- `npm run build` で型エラーが出ている
- Pages の設定が **GitHub Actions** になっていない
  （Settings → Pages → Build and deployment → Source）

## 8. 現在の制限事項

- **長い文章はA4印刷時に収まりにくい**です。
  1ページに1か月分を収めるため、1行の高さは自動的に小さくなります（31日の月で約8.6mm）。
  1セルにはおおよそ **10〜20文字程度の短い予定** を入力する前提でお使いください。
  長すぎる文章を入れると、印刷時に文字が隠れたり、行の高さが伸びて
  1ページに収まらなくなることがあります。
  なお、**保存されているデータ自体が削られることはありません**（画面上では全文を確認できます）。
- **祝日の自動表示には対応していません。**
  祝日・行事は「みんなの予定」欄へ手で入力してお使いください。
- **端末間で予定は同期されません**（上の「2. 予定はどこに保存されるのか」を参照）。
- **スマートフォン専用の画面はありません。** 狭い画面では表を横スクロールしてお使いください。
- 印刷は主にパソコンでの利用を想定しています。
